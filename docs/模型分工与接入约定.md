按业务用途而非查看者身份选型：教师交互／建议和学生学伴使用 Sol，评分及结果总结使用 Terra；教师查看的冻结报告总结也走 Terra/high 的 `summary`，不作为学伴 `response`。其他学生学习结束摘要、学习印象及班级总结仍遵循这一用途选型，但不能仅凭路由声明为已实现业务。正式配置必须显式保留 `teacher`、`student`、`grading`、`summary` 四个通道，依次为 Sol／Sol／Terra／Terra，全部 `high`；`grading`、`summary` 缺失时拒绝对应调用，不回落到 `student`。网关不会在请求失败后静默切换其他型号、密钥或旧客户端。

正式平台使用 `server/app/services/model_gateway.py` 的独立 `ModelGateway`。`LLMClient` 是旧项目保留的兼容适配器，其通道回退和非流式行为不代表正式网关能力，也不是正式网关的隐式后备。第四阶段已接通受限 `summary` 与 `hint` 业务；它们只允许模型选择有限代码，由服务器模板生成可见文字，不代表开放式诊断或辅导质量已验收。

客观题规则评分和数据库进度查询仍由程序完成。语音转写、数学口述转公式、扫描资料识别的具体供应商能力尚未实测，不能仅凭模型名称视为已支持。

## 请求参数与流式边界

已在登录态模型广场核对到 `gpt-5.6-sol` 和 `gpt-5.6-terra`，两者均列有 `high` 档位。`high` 作为请求参数传递，不拼进 model ID，不自动替换为其他型号。正式网关使用 OpenAI Chat Completions 风格，学生流式请求的主要字段为：

```json
{
  "model": "gpt-5.6-sol",
  "reasoning_effort": "high",
  "messages": [],
  "stream": true,
  "stream_options": {"include_usage": true}
}
```

实际请求须带合法消息；上例只展示自由学伴流式字段约定。教师用途同样使用 `gpt-5.6-sol`，评分及摘要使用 `gpt-5.6-terra`，推理强度均为 `high`。网关已实现非流式与 SSE 解析，自由学伴流式只采纳公开的 `delta.content`，不展示或留存隐藏推理。受限 `hint` 使用非流式严格 JSON，只接受 `action_id`，不公开原始模型输出或 `delta`；`summary` 也须先通过冻结事实校验，再由服务器模板生成正文。若改接 Responses API，需另行适配 `reasoning.effort`，不能照搬当前请求。

正式学生学伴已接通会话、消息、后台回答、持久片段 SSE 与 GET 只读恢复。每次获准 SSE 连接／重连的第一帧均为按当前授权和答案政策投影的权威 `snapshot`；文本、代次和事件游标从同一读取事务取得，客户端替换旧前缀后再接收已提交的新片段。队列状态、取消请求、待对账或待结算标记变化，即使游标不变也可通过快照通知。断线或刷新通过同一回答的消息历史、回答快照和事件游标只读恢复，不通过再次 POST 消息产生新调用。已有本机夹具验证使用注入的假网关，不能据此宣称学生 Sol 线路支持真实流式或已核对供应商账单；评分和摘要 Terra 的真实供应商能力与质量仍属第五阶段待验收。

`reconciling`／`awaiting_confirmation` 显示核对调用结果、核对费用或等待确认等暂停原因，提供“刷新状态”“取消本次回答”。`web/prototype/app.js` 还允许 `intent: hint`、回答为 `streaming`／`completed` 且 `job.status: failed` 时显示“确认恢复（可能产生费用）”；非 hint 保持原有暂停条件和 `awaiting_confirmation` 恢复规则。`cost_pending`、`reconciliation_required`、`cancel_requested` 任一为真，或回答自身为 `failed`／`cancelled`／`revoked` 时，不显示也不执行恢复。

用户明确确认后提交 `confirm_paid: true`，只恢复原作业并读取／订阅原回答，不另发消息；已持久成功 call／checkpoint 的 hint 恢复复用结果，不因按钮的通用费用提示而再次付费。明确取消 `failed` 作业会设置 `cancel_requested: true` 并将队列设为 `cancelled`；公共 `POST /api/v1/jobs/{job_id}/resume` 对取消标记或 `cancelled` 状态返回 HTTP 409（`cancelled_job`），不据此声称底层 `JobQueue.retry` 禁止所有取消态重试。暂停／取消／确认恢复控件及存储故障恢复有自动化验证，尚未进行浏览器故障注入；学生正常流程的 GUI 覆盖范围见[验证记录与边界](验证记录与边界.md)。

## 配置与凭据

`server/.env.example` 提供正式分组、超时、输出上限与价格字段示例；配置示例不含可用密钥，也没有真实单价。

1. `LLM_PROVIDERS_JSON` 显式配置 `teacher`、`student`、`grading`、`summary`，模型依次为 `gpt-5.6-sol`、`gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-5.6-terra`。使用 `api_key_env` 指向凭据环境变量，不把密钥值写进 JSON。
2. 凭据由进程环境变量或密钥服务注入；本机 `.env` 仅保存非敏感配置。2026-11-15 当时仅检查配置启用状态和环境变量是否存在，未输出凭据值；当时本机 `.env` 未启用模型配置，进程环境未注入对应凭据。本次文档同步未读取或复核凭据环境。凭据、Cookie、激活码、数据库与运行产物均不得提交。
3. 供应商 base URL 使用 `https://www.poke2api.com/v1`，正式网关据此请求 `/v1/chat/completions`。实际分组由密钥权限及站点路由决定，不预设教师与学生线路权限相同。
4. 正式网关固定 `high`，交互与批处理分别使用 `LLM_INTERACTION_*`、`LLM_BATCH_*` 的超时和输出上限。现有默认值是配置基线，仍需真实小样验证时延、截断和费用。
5. 生成、审题和教师建议分别使用业务服务及提示词。审题应独立求解再比较参考答案并保留版本；同一 Sol 型号的独立复核不能称为跨模型交叉验证。

## 答案门禁与预算

答案政策以服务端为准。`GET /api/v1/companion/answer-policy` 合并学生全局政策与所选任务／题目政策；自由聊天仍须两者均允许才能生成，受限提示使用独立门禁，不扩大自由聊天权限。已出分任务不能绕过其他进行中任务。生成发送前、片段保存、最终提交以及历史、回答、事件读取时都按当前账号、课程／班级权限和答案政策核验；失权或政策收紧后收起不再允许展示的内容，SSE 可返回 `revoked`。

第四阶段 R29 已实现有界的两级受限提示：只面向正式当前题，须有服务端已保存的合法尝试，并匹配当前 `attempt_cycle`、`draft_hash` 及政策／校验器版本。模型只从有限动作中选择 `action_id`，可见内容为服务器固定模板，不判断选项对错或输出答案；无外发许可、坏输出、预算／配置不可用等情形回退固定 `safe_guidance`。首诊继续独立作答，无尝试等不满足条件的路径也保持固定引导。2026-11-15“活跃题只有固定引导”的旧状态不再代表此路径；受限提示仍不等于开放式逐步解题、课程检索、记忆增强或完整阶段 E 教学质量验收。

只有服务端写入的 `source: restricted_hint`、`status: validated_delivered` 且确定事件 ID、当前作答 cycle 匹配的事件计为本轮帮助；`requested`、`validated`、`fallback` 不计。旧无 `status` 的 help 记录按兼容规则保守处理，不回填成新的有效提示证据。`unknown` 调用与 `cost_pending` 保留待核对，核对完成后仍须明确确认恢复。

hint 在已付费的成功 call 或安全 checkpoint 持久化后，若后续交付写入发生 `sqlite3.OperationalError`，队列可为 `failed`，领域回答保留 `streaming` 或已落盘的 `completed`。确认恢复原作业只复用原成功 call 的结果或 checkpoint，不新建付费调用、不重复扣费；已 `completed` 的提示沿用原回答绑定补齐交付记录。恢复重查当前权限、作答绑定和费用状态，交付确认前隐藏提示；取消或撤权阻断采用，之后对账也不复活已取消结果。此存储错误保留规则限于该 hint 路径，不泛化为所有异常或其他用途均可恢复。

- 任务绑定消息由服务端从真实任务归属解析并冻结 `student_id/course_id/class_id/task_id`，带入 outbox 与作业，班级学生日额据此参与预算预占和结算。
- 无任务自由对话使用管理员明确配置的个人全局 `student_daily` 与 `project/platform` 额度，不任意选一个班级扣账。
- 额度通过已认证的 `PUT /api/v1/budgets/limits` 配置；管理员设置项目总额和个人全局日额，班级负责人设置所属班级内的学生日额。钱包 `fund` 不替代正式额度。
- `LLM_PRICES_JSON` 按 provider/model 保存版本化价格，必须明确 `version`、`currency`、`input_units_per_million`、`output_units_per_million`；输入／输出单价为每百万 token 的整数计费单位。
- 价格币种必须与 `BUDGET_CURRENCY` 一致。缺价格、缺适用预算或币种不一致时阻断付费请求。`site-credit` 是站内名义计费单位，不能视为法币兑换保证或供应商现金收费上限。
- 已发送请求但 usage 不明时保留 `cost_pending` 并等待对账，不以0结算，也不盲目重发未知结果。调用费用归集与业务是否采纳回答分别处理；取消时尚未完成的回答以 `cancelled` 收尾，已持久 `completed` 的领域结果保留，取消仍阻断提示投影与交付采用。已发生及待对账费用仍保留，未知调用的队列仍可为 `reconciling`。取消不等于免除费用，后续对账不复活回答；费用和结果未核对完成前也不能确认恢复。

## 冻结报告总结与下一轮边界

第四阶段 `summary` 从选定的完整目标报告冻结修订取得全体学生、全轮次证据，由程序按原版本规则复算 `facts`。模型只能选择与既定事实对应的有限解释码；严格拒绝未知或改写的数字、遗漏／新增学生、跨学生或未知证据引用，以及证据不足时的强断言。服务器固定模板生成总结和限制说明，目前只有目标级证据，不能定位具体薄弱知识点，也不能称为自由 AI 诊断。

总结使用独立 `teaching_insight` 领域，保存报告修订、输入 hash、幂等请求及 `generation`；创建、重放、读取、发送和采纳均重查权限。结果与通知 outbox 同事务保存；总结领域仅允许 `failed` 恢复，并须满足作业的费用／结果核对和明确确认门禁，取消不复活。active 管理员仅在作业与总结的完整资源绑定核验后访问 `/jobs` 元数据和对账入口，不能据此读取总结正文。

下一轮由规则从已审核题库确定性配卷，经过教师编辑 CAS、完整预览及 `confirm` 才发布到原目标 `max(round_no)+1`；排除已使用题族，且前轮完成、评分齐备才可推进。持续计划须由教师明确确认有限题池、轮数和截止，缺题、未完成、待评分或撤权时暂停，不自动造题。对应正式接口、六库版本与恢复约束见[后端接入说明](decisions-backend-platform.md)。
