# 模型分工与接入约定

更新日期：2026-11-15；型号选择沿用2026-11-10确认结果。用户指定先使用 Poke API 的两个站内型号。学生侧原选 `gpt-5.5`，因当时测试密钥分组不支持，改为 `gpt-5.6-terra`，推理强度仍为 `high`。

## 业务用途与正式网关

| 业务用途 | 站内 API model ID | 推理强度 | `ModelGateway` 用途／通道 |
| --- | --- | --- | --- |
| 教师端 AI 回复、教学建议与教师主动分析 | `gpt-5.6-sol` | `high` | `teacher`、`suggest` → `teacher` |
| 出题、生成答案／解析／评分要点 | `gpt-5.6-sol` | `high` | `generate` → `teacher` |
| 审题、题库质量复审与修改建议 | `gpt-5.6-sol` | `high` | `review` → `teacher` |
| 学生学伴对话与学生侧文字任务 | `gpt-5.6-terra` | `high` | `student` → `student` |
| 学生简答 AI 评分、评分解释及自动复核 | `gpt-5.6-terra` | `high` | `grading` → `grading` |
| 学生学习结束摘要、学习印象、班级及报告内的结果总结 | `gpt-5.6-terra` | `high` | `summary` → `summary` |

按业务用途而非查看者身份选型：教师主动分析／建议使用 Sol，已生成教学结果的总结文字使用 Terra。正式配置解析器与网关已支持 `summary`；`grading`、`summary` 未单列时可使用 `student` 通道，仍须是 Terra/high，建议保留显式分组便于核账。网关不会在请求失败后静默切换其他型号、密钥或旧客户端。

正式平台使用 `server/app/services/model_gateway.py` 的独立 `ModelGateway`。`LLMClient` 是旧项目保留的兼容适配器，其通道回退和非流式行为不代表正式网关能力，也不是正式网关的隐式后备。用途路由已实现不等于各项业务的真实生成质量已验收；其中 `hint` 用途的存在也不表示 R29 逐步提示已开放。

客观题规则评分和数据库进度查询仍由程序完成。语音转写、数学口述转公式、扫描资料识别的具体供应商能力尚未实测，不能仅凭模型名称视为已支持。

## 请求参数与流式边界

已在登录态模型广场核对到 `gpt-5.6-sol` 和 `gpt-5.6-terra`，两者均列有 `high` 档位。`high` 作为请求参数传递，不拼进 model ID，不自动替换为其他型号。正式网关使用 OpenAI Chat Completions 风格，学生流式请求的主要字段为：

```json
{
  "model": "gpt-5.6-terra",
  "reasoning_effort": "high",
  "messages": [],
  "stream": true,
  "stream_options": {"include_usage": true}
}
```

实际请求须带合法消息；上例只展示字段约定。教师用途使用 `gpt-5.6-sol`，推理强度相同。网关已实现非流式与 SSE 解析，流式只采纳公开的 `delta.content`，不展示或留存隐藏推理。若改接 Responses API，需另行适配 `reasoning.effort`，不能照搬当前请求。

正式学生学伴已接通会话、消息、后台回答、持久片段 SSE 与 GET 只读恢复。每次获准 SSE 连接／重连的第一帧均为按当前授权和答案政策投影的权威 `snapshot`；文本、代次和事件游标从同一读取事务取得，客户端替换旧前缀后再接收已提交的新片段。队列状态、取消请求、待对账或待结算标记变化，即使游标不变也可通过快照通知。断线或刷新通过同一回答的消息历史、回答快照和事件游标只读恢复，不通过再次 POST 消息产生新调用。当前本机夹具验证使用注入的假网关，不能据此宣称真实 Terra 线路支持流式或已核对供应商账单。

`reconciling`／`awaiting_confirmation` 显示核对调用结果、核对费用或等待确认等暂停原因，提供“刷新状态”“取消本次回答”。费用未结清或调用结果仍待对账时，前后端均阻止恢复；仅在 `awaiting_confirmation` 且待结算、待对账和取消标记均已清除时显示“确认恢复（可能产生费用）”。该操作明确提交 `confirm_paid: true`，只恢复原作业／回答，不另发消息；已取消的回答不允许恢复。新增暂停／取消／确认恢复控件仅经自动化验证，未追加 GUI 验收。

## 配置与凭据

`server/.env.example` 提供正式分组、超时、输出上限与价格字段示例；配置示例不含可用密钥，也没有真实单价。

1. `LLM_PROVIDERS_JSON` 按 `teacher`、`student`、`grading`、`summary` 分组，保留准确 model ID。使用 `api_key_env` 指向凭据环境变量，例如 `POKE_TEACHER_API_KEY`、`POKE_STUDENT_API_KEY`，不把密钥值写进 JSON。
2. 凭据由进程环境变量或密钥服务注入；本机 `.env` 仅保存非敏感配置。凭据、Cookie、激活码、数据库与运行产物均不得提交，也不在检查配置时输出凭据值。
3. 供应商 base URL 使用 `https://www.poke2api.com/v1`，正式网关据此请求 `/v1/chat/completions`。实际分组由密钥权限及站点路由决定，不预设教师与学生线路权限相同。
4. 正式网关固定 `high`，交互与批处理分别使用 `LLM_INTERACTION_*`、`LLM_BATCH_*` 的超时和输出上限。现有默认值是配置基线，仍需真实小样验证时延、截断和费用。
5. 生成、审题和教师建议分别使用业务服务及提示词。审题应独立求解再比较参考答案并保留版本；同一 Sol 型号的独立复核不能称为跨模型交叉验证。

## 答案门禁与预算

答案政策以服务端为准。`GET /api/v1/companion/answer-policy` 合并学生全局政策与所选任务／题目政策；两者均允许才能生成。已出分任务不能绕过其他进行中任务。生成发送前、片段保存、最终提交以及历史、回答、事件读取时都按当前账号、课程／班级权限和答案政策核验；失权或政策收紧后收起不再允许展示的内容，SSE 可返回 `revoked`。

活跃任务与首诊仍采用固定 `safe_guidance`，安全引导不创建付费模型调用。首诊保持独立作答；普通作答根据是否已尝试返回相应固定引导。此处没有完成 R29 的逐步解题提示，也没有完成阶段 E、课程检索、记忆增强或开放式辅导教学质量验收。

- 任务绑定消息由服务端从真实任务归属解析并冻结 `student_id/course_id/class_id/task_id`，带入 outbox 与作业，班级学生日额据此参与预算预占和结算。
- 无任务自由对话使用管理员明确配置的个人全局 `student_daily` 与 `project/platform` 额度，不任意选一个班级扣账。
- 额度通过已认证的 `PUT /api/v1/budgets/limits` 配置；管理员设置项目总额和个人全局日额，班级负责人设置所属班级内的学生日额。钱包 `fund` 不替代正式额度。
- `LLM_PRICES_JSON` 按 provider/model 保存版本化价格，必须明确 `version`、`currency`、`input_units_per_million`、`output_units_per_million`；输入／输出单价为每百万 token 的整数计费单位。
- 价格币种必须与 `BUDGET_CURRENCY` 一致。缺价格、缺适用预算或币种不一致时阻断付费请求。`site-credit` 是站内名义计费单位，不能视为法币兑换保证或供应商现金收费上限。
- 已发送请求但 usage 不明时保留 `cost_pending` 并等待对账，不以0结算，也不盲目重发未知结果。调用费用归集与业务是否采纳回答分别处理；取消回答的终态为 `cancelled`，已发生及待对账费用仍保留，未知调用的队列仍可为 `reconciling`。取消不等于免除费用，后续对账不复活回答；费用和结果未核对完成前也不能确认恢复。
