# 模型分工与接入约定

确认日期：2026-11-10。用户指定先使用 Poke API 的两个站内型号，替代此前的多供应商候选组合。学生侧原选 `gpt-5.5`，因当前测试密钥分组不支持，按用户最新要求改为 `gpt-5.6-terra`，推理强度仍为 `high`。

| 业务用途 | 站内 API model ID | 推理强度 | 当前配置通道 |
| --- | --- | --- | --- |
| 教师端 AI 回复、教学建议与教师侧分析 | `gpt-5.6-sol` | `high` | `teacher` |
| 出题、生成答案/解析/评分要点 | `gpt-5.6-sol` | `high` | `teacher` |
| 审题、题库质量复审与修改建议 | `gpt-5.6-sol` | `high` | `teacher` |
| 学生学伴对话、分步提示和自主学习辅导 | `gpt-5.6-terra` | `high` | `student` |
| 学生简答 AI 评分、评分解释及自动复核 | `gpt-5.6-terra` | `high` | `grading` |
| 学生学习结束摘要、简短学习印象等学生侧文字任务 | `gpt-5.6-terra` | `high` | `student` |
| 班级总结及教学报告内的 AI 文字总结 | `gpt-5.6-terra` | `high` | 后续新增 `summary` 用途；未接入前显式走学生模型 |

后续总方案见[产品与前后端技术总方案](智慧学伴产品与前后端技术总方案.md)§11.1：按业务用途而非查看者身份选型，教师主动分析/建议使用Sol，已生成教学结果的总结文字使用Terra；本表的用途划分不代表这些业务已经接通。新增 `summary` 为设计用途，现有配置解析器尚不支持该通道，不能直接把它填入 `LLM_PROVIDERS_JSON`。

客观题规则评分和数据库进度查询仍由程序完成，不因为选定模型而改成 AI 调用。语音转写、数学口述转公式、扫描资料识别的具体接口能力尚未在这两条线路实测，不能仅凭模型名称视为已支持。

## 型号与参数

已在登录态模型广场核对到 `gpt-5.6-sol` 和 `gpt-5.6-terra`，两者均列有 `high` 档位。`high` 作为请求参数传递，不拼进 model ID，不自动替换为 `gpt-6-sol`、`gpt-6.1-sol` 或其他型号。

当前 `LLMClient` 使用 OpenAI Chat Completions 风格：

```json
{
  "model": "gpt-5.6-sol",
  "reasoning_effort": "high",
  "messages": []
}
```

学生侧改用 `"model": "gpt-5.6-terra"`，其余推理强度相同。若未来使用 Responses API，需单独适配其 `reasoning.effort` 字段，不能照搬当前适配器请求。

## 配置方式

`server/.env.example` 已提供禁用状态的多通道配置示例及 `LLM_REASONING_EFFORT=high`。

1. 在本地 `server/.env` 或部署环境中填写 `POKE_TEACHER_API_KEY`、`POKE_STUDENT_API_KEY`；不提交真实密钥。
2. 根据实际购买/绑定的分组创建密钥，确保教师密钥可调用 `gpt-5.6-sol`，学生密钥可调用 `gpt-5.6-terra`。同一个可用密钥也可以分别填入两项，但不预设两条线路权限相同。
3. 启用示例中的 `LLM_PROVIDERS_JSON`。此适配器会在 base URL 后追加 `/chat/completions`，因此配置使用 `https://www.poke2api.com/v1`，最终请求路径为 `/v1/chat/completions`。
4. 当前全局 `LLM_REASONING_EFFORT=high` 作用于这三个通道；保留显式 `grading` 配置，学生作答评分不走教师出题通道。
5. 生成、审题、教师回复将来分别编写业务服务和提示词，但使用同一个教师型号。审题请求应独立求解后比较参考答案，保留审查依据和版本；这属于同模型独立复核，不能称为跨模型交叉验证。

同名模型在站内存在多个分组，实际分组由密钥权限及站点路由决定；本次没有替用户创建密钥、选择付费分组或添加未知的分组 ID。接入时应记录实际使用的型号和线路，不能静默换成其他模型或较低推理档位。

## 当前落地状态

配置模板仍默认禁用，没有填写或保存本地密钥。2026-11-10 的最小连接测试中，`gpt-5.6-sol` 携带 `high` 参数返回 HTTP 200 和 `OK`；原学生型号 `gpt-5.5` 返回 HTTP 403 `MODEL_UNSUPPORTED`，提示当前密钥分组不支持。随后学生侧改选 `gpt-5.6-terra`；本次尝试因测试凭据不可用而在发送请求前停止，Terra 的真实连接状态仍未验证。接口接受请求不代表已验证实际教学质量、上游模型身份或推理档位执行效果。

现有样例和任务路由仍为离线规则流程。配置适配器不代表学生聊天、教师 AI 回复、自动题库生成/审查等新业务已经实现；它们按产品方案继续接入。现有适配器为非流式，当前默认输出上限和超时也不能视为已适配高强度推理，需要在接入时通过真实小样测试确定，并为出题/审题与学生交互分别设置预算和超时。

接入验收至少检查：两个准确 model ID 与 high 参数确实发出、密钥分组支持相应模型、推理后的完整答案未被输出上限截断、结构化结果可校验、响应时间、计费输出与实际账单。测试先使用虚构题目或获准外发的资料。

站点入口：[模型广场](https://www.poke2api.com/model-square)、[接入文档](https://docs.poke2api.com/guide/api-scripts)。站内型号及渠道名称是站点声明，本次核对不构成对上游真实身份或服务质量的验证。
