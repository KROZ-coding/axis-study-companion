## 适合智慧学伴的参考

| 老师展示内容 | 可迁移到本题的设计 |
| --- | --- |
| 资源库分类 | 统一管理课程要求、材料和练习，保留编号、出处及解析状态 |
| 群体学情与个人报告 | 教师先看共性问题，再进入学生证据；学生查看个人表现与后续任务 |
| 学习报告与建议相邻呈现 | 让分析结果连接具体练习、材料与行动，不把报告当成终点 |
| 知识、能力、问题分类 | 根据实际字段建立课程要求、作答记录和学习建议的对应关系 |
| 操作反馈与历史记录 | 对导入、分析、调整建议等操作提供明确结果和留痕 |

课程思政、勋章、点名等属于参考平台的具体场景，不直接作为本题必要功能。画像、能力评分和学习趋势必须有数据依据。

## 视觉上需要调整的现象

- 多页重复顶部四个数字卡片与下方大面板，页面任务不同但布局近似。
- 大圆角卡片中继续嵌套卡片，容器层级偏多。
- 多处蓝绿渐变、渐变标题与按钮，视觉强调范围过大。
- 只有少量记录的区域占据很大的固定面板，信息密度偏低。
- 彩色表情、阴影与浮动人物头像重复出现，容易分散注意力。

这些是模板观感的具体来源，不足以证明页面由AI生成。

建议按真实任务组织布局：材料页用目录和列表，学情页用表格及分布，学生详情用证据面板，报告页用适合阅读的排版。颜色主要服务状态、选择和主要操作，动效主要用于反馈。

必须区分暂无数据、尚未完成测验和已有证据显示薄弱，避免把缺失记录直接显示成零分风险。

## 技能候选

### Impeccable：优先候选

核对了其技能源文件及Operate模式规则。该模式适用于工作台，强调可扫描性、统一控件、克制用色和任务效率，允许合理信息密度。

建议使用顺序：`critique`评估，`distill`简化，`layout`与`typeset`调整布局排版，`polish`打磨。具体使用仍以安装版本的规则为准。

截至本次整理，仅完成检索，尚未安装或用于修改页面。

来源：

- https://impeccable.style/
- https://github.com/pbakaus/impeccable
- https://github.com/pbakaus/impeccable/blob/main/skill/SKILL.src.md
- https://github.com/pbakaus/impeccable/blob/main/skill/reference/operate.md

### frontend-design：辅助候选

适合建立新页面的视觉方向。使用时需明确教学工作台的用户任务和信息密度，避免默认采用宣传页的大标题与装饰。

来源：https://skills.sh/anthropics/skills/frontend-design

### emil-design-eng：已有本地技能

适合在结构确定后打磨按钮、弹层、交互状态与动效。

本次检索还发现，`redesign-existing-projects`条目已停用并指向替代技能，不按旧教程直接安装。

## 当前结论

先明确用户操作和证据展示方式，再统一排版、间距、颜色及控件。功能参考老师展示，是否采用具体分析能力取决于正式数据；不把整套教学平台功能全部搬入作品。
