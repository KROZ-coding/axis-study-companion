# 六库停写备份、离线校验与隔离恢复

适用于正式 `server/` 的六个 SQLite 域：`platform`、`learning`、`jobs`、`content`、`reports`、`companion`。工具入口为 `python -m app.backup_cli`，复用 `app.backup.BackupManager`、默认六库 schema 合同、`write_backup`、`inspect` 和 `restore_to_staging`，不启动应用，不加载 `server/.env`，不选择模型或发起网络请求。

## 操作前提

从正式 `server/` 目录使用已安装依赖的 Python 运行；所有路径建议写绝对路径。`--data-dir` 必须明确提供，不读取环境变量或 `.env` 推测目录；相对 `--data-dir` 与 Runtime 一致，以 `server/` 为基准。备份文件、staging 等其他相对路径以当前工作目录为基准。

先停止 API、内嵌 worker、独立 worker、定时任务、导入脚本和其他写进程，并确认退出及写入已经停止。备份、恢复命令强制要求 `--stopped`，它仅记录操作者的停写声明，**工具无法据此证明已经停写**，不会自动停止进程或锁住全部写入。六库快照逐库取得，即使 SQLite backup API 能读取已提交 WAL，也不能保证持续跨库写入期间的同一业务时点。

提前创建仅授权运维人员可访问的备份父目录和隔离恢复父目录；都应位于正式 DATA_DIR 之外。不要将仓库根、`server/` 或用户主目录当作 DATA_DIR。恢复期间继续保持正式实例停写，以免旧实例与恢复实例同时产生业务和费用。

## 命令

下例中的 `/srv/study/data`、`/srv/study-backups`、`/srv/study-recovery` 是部署路径示例，应换成已确认的实际绝对路径；每次使用新的备份文件名。

```sh
python -m app.backup_cli --help

python -m app.backup_cli backup \
  --data-dir /srv/study/data \
  --output /srv/study-backups/study-20261117-001.zip \
  --stopped

python -m app.backup_cli verify \
  --bundle /srv/study-backups/study-20261117-001.zip

python -m app.backup_cli restore \
  --bundle /srv/study-backups/study-20261117-001.zip \
  --data-dir /srv/study/data \
  --staging-parent /srv/study-recovery \
  --stopped
```

PowerShell 可使用同样参数写在一行，或以反引号续行；例如在正式 `server/` 中使用 `\.venv\Scripts\python.exe` 时，应写为 `.\.venv\Scripts\python.exe -m app.backup_cli ...`。

成功时 stdout 为一行 JSON，`ok: true`，退出码为 0；校验或操作失败时退出码为 2，错误写入 stderr，不输出堆栈、数据库行、会话令牌或供应商配置。成功输出包含六库版本、application_id、文件大小与 SHA256、附件数、整包 `bundle_sha256`；不列出附件原始文件名或业务正文。

可把备份输出的整包 SHA256 独立保存在可信记录中，再在校验或恢复时添加 `--sha256 <64位十六进制摘要>`。内部清单和 SHA256 能检测损坏，不能证明备份来源；可信整包摘要或受控备份存储仍由运维管理。

默认压缩包及解压后总大小上限均为 734003200 字节（700 MiB），三个命令都可明确设置 `--max-bytes <正整数>`。大备份有内存和临时磁盘开销，不支持无限流式备份；临时目录也应位于受控磁盘。

## 备份范围与拒绝覆盖

六库必须全部存在并符合当前默认 schema 合同。只备份六库 SQLite 快照，不直接复制 WAL/SHM/journal。SQLite 完整性、外键、版本、application_id、精确表集合及每个文件的 SHA256/大小由核心实现校验；CLI 在发布包前还会重新 `inspect`。

附件按以下 Runtime 布局收集，保持相对路径；没有该目录时按空目录处理。

| DATA_DIR 中的路径 | 包内路径 | 恢复后的路径 |
| --- | --- | --- |
| `material_originals/` | `attachments/material_originals/` | `data/material_originals/` |
| `attachments/`、`documents/` | `attachments/shared/<原相对路径>` | `data/<原相对路径>` |
| `reports/`、`exports/`、`report_exports/` | `attachments/shared/<原相对路径>` | `data/<原相对路径>` |
| `knowledge/` | `attachments/shared/knowledge/` | `data/knowledge/` |
| 六个 `<域>.sqlite3` | `databases/<域>.sqlite3` | `data/<域>.sqlite3` |

正式报告的冻结快照、修订、总结与 outbox 本身保存在 `reports.sqlite3`；正式导出接口直接生成下载内容，不要求本地存在 `reports/`。若运维在 DATA_DIR 内上述目录保存了资料或报告副本，会按附件一起备份。`material_originals` 不会重复混入 shared 根。

CLI 不遍历整个 DATA_DIR，不带出根目录任意文件；已知附件树内还排除隐藏文件／目录（包括 `.env*`）、日志／run／tmp／cache／凭据目录、PID/lock/socket、私钥／证书容器及 SQLite 主文件和旁文件等。符号链接、Windows reparse point 和非常规附件文件会被拒绝。工具无法从普通附件正文中识别所有人为嵌入的秘密：凭据仍应由部署环境单独管理，普通附件目录也不应存放秘密。额外自定义附件根不在当前 CLI 的支持范围内，迁入前应先核对目录覆盖，不要把进程产物改名伪装为附件。

备份目标父目录必须已经存在，目标文件必须不存在，并且必须位于 DATA_DIR 外。CLI 在同文件系统私有临时目录内调用原子 `write_backup`，校验成功后通过不覆盖目标的原子 hard link 发布；另一进程抢先创建同名目标也会失败，旧文件保持原样。不支持 hard link 的目标文件系统会报错，不回退到覆盖写入。POSIX 文件权限收紧至 0600、临时目录 0700；Windows 的最终访问权限仍需依靠父目录 ACL。备份含账号哈希、会话及教学数据，需按敏感数据管理、加密保存与受控转移。

## 离线校验

`verify` 不接受 DATA_DIR，不实例化 Runtime，不打开任何活库；只读备份文件，在临时目录中用 `mode=ro&immutable=1` 检查独立 SQLite 副本。它还检查附件路径是否能安全装配当前 Runtime 布局，拒绝未知附件根、受排除文件和不区分大小写的路径冲突。

校验成功证明该包符合当前六库和附件合同，不证明生产数据已停写、附件来源许可、业务事实完整、跨库一致或供应商账单已核对。

## 新目录恢复与上线前门禁

`restore` 的 `--data-dir` 是需要保护的正式活库目录，源库文件不会被打开；`--staging-parent` 必须是现有目录，不能等于或位于该活库目录内部。工具调用 `restore_to_staging` 创建新的 `restore-<随机值>`，再装配 `restore-<随机值>/data`；重复执行总是得到不同目录，不能指定覆盖现库，也没有在线热恢复或自动切换入口。装配失败会清理本次新恢复目录，不改正式数据。

从成功 JSON 的 `data_dir` 字段取得装配好的目录。六库直接位于该目录，资料原件位于其 `material_originals/`，其余资料／报告按原相对路径恢复。恢复返回前重新核对主库与附件 SHA256；使用 immutable 只读查询统计未决状态，不生成 WAL/SHM/journal。之后正常 Runtime 打开 WAL 数据库时可以产生旁文件。

恢复结果始终为 `ready_for_production: false`。`recovery_review` 只返回作业状态计数、调用状态计数、待对账／待结算、取消标记及持久租约数量；这些计数来自备份时点，不会自动修复业务状态，不构成可直接上线的批准。按以下顺序复核。

1. 保持恢复实例 `STUDY_WORKER_ENABLED=false`，不注入供应商凭据并保持外网调用禁用；先检查装配目录、六库、资料原件、历史报告和权限边界。CLI 不会启动该实例，也不会为它写配置；如手工启动复验，需明确设置新的绝对 `DATA_DIR`，勿继承原实例的配置文件。
2. 核对恢复的会话、账号状态与权限，处理回滚到旧会话／口令状态的影响；核对草稿租约、队列租约与 generation、跨库 outbox、提示 checkpoint 与回答／任务绑定。CLI 保留原事实，不清空会话、租约、费用或 checkpoint。
3. 对 `in_flight`／`unknown` 调用先依据真实供应商记录核对结果，再核对 usage、价格版本和最终费用。`unknown`、`cost_pending` 或 `reconciliation_required` 不按零费用处理，不盲目重发；取消也不清除已发生和待核对费用。
4. 非自动恢复的付费工作在结果与费用核对完成后，仍须用户明确确认恢复原作业。公共 `/api/v1/jobs/{job_id}/resume` 使用 `confirm_paid: true`，并受取消、当前授权和领域状态门禁约束；取消作业不能通过公共恢复入口复活。已有成功结果／安全 checkpoint 按现有恢复契约复用，不创建替代消息或无依据的新调用。评分有既定自动恢复规则，因此未完成复核前尤其不能提前开启 worker。
5. 仅在上述检查、受控实例复验及部署切换决策完成后，由运维单独安排切换；避免原实例和恢复实例并行写入或付费。备份时点之后已经发送到供应商的调用可能不在包里，须结合独立账单／请求记录核对，不能只看恢复库计数。

## 自动化证据与边界

`server/tests/test_backup_cli.py` 使用真实临时 Runtime 六库与上传原件、报告、会话、队列，不读取正式 DATA_DIR 或 `server/.env`；网络连接和 HTTP 传输均设断言拦截。覆盖显式停写声明、普通目标及并发抢占目标不覆盖、离线校验不打开活库、隔离目录及 Runtime 装配、损坏／整包摘要／非法附件拒绝、WAL 已提交内容、恢复后未决付费调用／待费用／明确确认门禁和成功结果复用、模块入口不导入配置及错误脱敏。

2026-11-17 定向结果：新增 CLI **10/10** 通过（10.194 秒）。此为本机临时真实 SQLite 自动化证据，不是实际服务器停服演练、跨主机灾备、Windows ACL、外部加密存储或真实供应商账单验收。联合现有迁移备份回归的结果以本次测试执行输出为准。完整后端测试可从仓库根目录运行：

```sh
python -I -B -X utf8 server/tests/run_tests.py
```
