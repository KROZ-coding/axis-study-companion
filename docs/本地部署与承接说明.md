## 本地启动正式平台

要求 Python 3.11+；前端原生 ES 模块，无构建步骤。以下 PowerShell 命令均从仓库根目录执行：

```powershell
python -m venv server/.venv
.\server\.venv\Scripts\python.exe -m pip install -r server/requirements.txt

$env:SKIP_ENV_FILE = "1"
$env:APP_ENV = "development"
$env:STUDY_DEMO_ENABLED = "false"
$env:STUDY_WORKER_ENABLED = "true"
$env:DATA_DIR = "./data/platform"
$env:COOKIE_SECURE = "false"
$env:STUDY_COMPANION_PORT = "8000"

Push-Location server
.\.venv\Scripts\python.exe -m app.init_admin --username your-admin --display-name 管理员
Pop-Location

.\start_study_companion.bat
```

首次管理员密码由终端隐藏输入，不设默认账号或密码；已有管理员的实例不重复初始化。后续沿用相同配置启动即可。相对 `DATA_DIR` 按 `server/` 解析；上例保存到 `server/data/platform/`。正式数据分别存于 platform、learning、jobs、content、reports、companion 六个 SQLite 文件；旧样例的 `STUDY_DATA_DIR` 不是正式平台数据入口。

访问 <http://127.0.0.1:8000/prototype/> 登录进入师生工作区；<http://127.0.0.1:8000/health> 检查模式和 worker。正式写请求需同源 `Origin`，认证使用 Cookie，旧演示身份头不参与正式授权。启动脚本仅监听 `127.0.0.1`，`COOKIE_SECURE=false` 用于本机 HTTP；窗口保持运行，按 Ctrl+C 停止。

不用启动脚本时，在相同环境中执行：

```powershell
.\server\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir server --host 127.0.0.1 --port 8000
```

## 学生学伴、只读恢复与确认继续

学生端已接新建／命名／切换及归档恢复会话、发送消息、后台排队与 SSE 回答；命名采用带可访问标签的行内表单，替换浏览器 `prompt`。任务作答页“问学伴”携带可编辑的题目、选项和自己的尝试，确认后发送；返回时重新读取服务端权威任务并获取编辑租约，未修改的本地缓存不遮蔽服务端草稿，修复已有自动回归及双视口 GUI 复验。

- `GET /api/v1/companion/answer-policy` 返回服务端合并的全局与任务／题目政策，不由前端猜测可否生成。
- `POST /api/v1/companion/conversations/{id}/messages` 持久化用户消息与作业意图，稳定 `request_id` 用于结果不明时的同载荷幂等重试。
- `GET /api/v1/companion/responses/{id}/stream` 支持 `Last-Event-ID`／`after`。每次获准连接／重连第一帧都是当前授权和答案政策投影下的权威 `snapshot`，文本、代次和事件游标由同一读取事务取得；客户端替换旧前缀后接收已持久化的新片段。队列状态、取消请求、待对账或待结算标记变化，即使游标不变也可通过快照通知。
- 刷新或流中断时，使用消息历史、同一回答及事件的 GET 只读恢复；不会再次提交消息或启动新上游调用。
- `reconciling`／`awaiting_confirmation` 显示暂停原因，提供“刷新状态”“取消本次回答”。费用未结清或调用结果仍待对账时，前后端均阻止恢复；仅在 `awaiting_confirmation` 且待结算、待对账和取消标记均已清除时显示“确认恢复（可能产生费用）”。该操作向原作业 `/api/v1/jobs/{job_id}/resume` 明确提交 `confirm_paid: true`，只恢复原作业／回答，不新建消息。
- 取消向原作业 `/api/v1/jobs/{job_id}/cancel` 提交请求，回答终态为 `cancelled`；已发生和待对账费用继续保留，未知调用的队列仍可保持 `reconciling`。取消不清零费用，对账完成也不自动恢复已取消回答。新增暂停／取消／确认恢复控件只有自动化证据，未追加 GUI 验收。

生成、历史与流式输出均检查当前账号、课程／班级权限及答案政策，已出分任务不能绕过其他进行中任务。活跃任务和首诊仍返回固定 `safe_guidance`，不调用付费模型；本轮未完成 R29 逐步提示、完整阶段 E、课程检索、记忆增强或真实模型质量验收。

## 真实模型配置与预算

教师交互／出题／审题固定 Sol/high，学生／评分／结果总结固定 Terra/high，正式网关已支持 `summary`。凭据通过进程环境变量或密钥服务注入，`LLM_PROVIDERS_JSON` 只保存 `api_key_env` 引用；本机 `.env` 仅放非敏感配置，凭据与运行数据不提交。配置字段见 `server/.env.example`，完整规则见[模型分工与接入约定](模型分工与接入约定.md)。

价格按 provider/model 保存版本、明确币种和每百万 token 的输入／输出整数单价，且币种须匹配 `BUDGET_CURRENCY`。通过 `PUT /api/v1/budgets/limits` 配置额度：任务消息使用服务端解析冻结的学生／课程／班级范围；无任务自由聊天使用个人全局日额和 `project/platform` 总额，不随意取某班额度。缺价格、缺适用预算或币种不一致均阻断付费请求；未知 usage 保持 `cost_pending` 等待对账。名义 `site-credit` 不保证法币兑换或供应商现金收费上限，钱包 `fund` 不替代额度配置。

本轮真实 Terra／价格／预算联调**未执行**，原因是尚无已确认单价、币种和总调用额度。2026-11-10 的 Sol/high HTTP 200 仅为历史最小连接记录，不能代表当前真实供应商验收。

## 旧样例与数据边界

仅在独立实例中设置 `APP_ENV=development`、`STUDY_DEMO_ENABLED=true` 和独立 `STUDY_DATA_DIR` 才开启旧样例：根页面为 `web/` 旧网页，`/health` 返回 `offline-sample`，路由为 `/api/study/*`、`/api/teaching/*`，不混合正式 `/api/v1`。50名学生、知识点统计与固定引导均为虚构规则样例，师生视角切换不是正式身份验证；`demo/` 保留原静态原型。

旧压缩快照的解码和 dry-run 与正式六库分开，真实账号映射及旧事实导入仍禁用。正式备份应停写后覆盖六库、附件与校验清单，仅恢复到隔离目录；逐库快照不保证持续跨库写入时的同一业务时点，细节见[正式后端接入说明](decisions-backend-platform.md)。

正式赛事资料、个人信息、上传原件、密钥、数据库和运行产物保持在忽略范围。未完成正式三名代表案例、两班比较或独立教学评测，合成数据与机读文件不是正式赛事成果。
