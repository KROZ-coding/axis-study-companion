# 本机教学工作区操作说明

本页对应 2026-11-18 的实现。独立入口使用 `STUDY_COMPETITION_UNMETERED=true`：不要求价格锚点、价格版本或站内预算，保存真实模型用量，金额保持 `null`。供应商实际收费由供应商决定。默认普通启动仍采用原计价模式。界面使用“学情分析、课程材料、分析记录”等教学名称；启动脚本、内部 API 和数据库标识继续兼容原名称。

## 本机配置与启动

从仓库根目录运行，依赖沿用 `server/.venv`。先创建不含密钥的本机配置，再在同一 PowerShell 进程隐藏输入凭据：

```powershell
.\start_competition.bat --setup
$teacherCredential = Read-Host '教师通道 API 凭据' -AsSecureString
$studentCredential = Read-Host '学生、评分与总结通道 API 凭据' -AsSecureString
$env:POKE_TEACHER_API_KEY = [System.Net.NetworkCredential]::new('', $teacherCredential).Password
$env:POKE_STUDENT_API_KEY = [System.Net.NetworkCredential]::new('', $studentCredential).Password
Remove-Variable teacherCredential, studentCredential
.\start_competition.bat --check
.\start_competition.bat --init-admin --username your-admin --display-name 管理员
.\start_competition.bat
```

`--setup` 只创建尚不存在的 `server/competition.local.json`，不会覆盖已有配置。schema version 2 仅保存 `teacher_key_env`、`student_key_env` 环境变量名、接口地址和数据目录，不保存密钥。默认引用 `POKE_TEACHER_API_KEY` / `POKE_STUDENT_API_KEY`；凭据只从明确的进程环境读取。已有管理员的实例跳过初始化。默认访问 [教学工作区](http://127.0.0.1:8001/prototype/)，数据独立保存在 `server/data/competition/`。

`--check` 只做离线检查，不发模型请求；线路及业务响应须另行实测。旧含 `teacher_key` / `student_key` 的本机文件会明确提示迁移，原文件不被自动覆盖；先将凭据移入环境变量，再移除密钥字段并改用 version 2 的变量名字段。结束进程后可执行 `Remove-Item Env:POKE_TEACHER_API_KEY, Env:POKE_STUDENT_API_KEY` 清除当前终端中的凭据。

可用 `--config <本机文件.local.json>` 读取另一个明确配置；`--data-dir <独立目录>` 指定本次实例的数据位置；`--port 8002` 改端口；`--teacher-key-env` / `--student-key-env` 可在 `--setup` 时指定其他变量名。所有命令使用同一配置和数据目录。评测验收使用另一个目录，后续正式资料通过页面重新添加。

默认接口为 `https://www.poke2api.com/v1/responses`，网关按完整地址使用 Responses 协议；显式 provider 配置也可设置 `api_type="responses"`。旧 `chat_completions` 协议仍支持，不能将两种完整接口地址混用。四通道显式路由：teacher/student 为 `gpt-5.6-sol`，grading/summary 为 `gpt-5.6-terra`，推理强度为 `high`。缺用量保留待核对；请求结果未知时保留对账状态，核对原请求后再明确恢复，不自动重发。

## 用课程资料生成题目

1. 从教师账号进入有权限的课程，在“题库与材料 → 课程材料”上传资料，或粘贴已核对的原文。粘贴完整 CSV 时选择 CSV 格式，保留表头、引号与换行；填写实际文件名和来源位置。
2. 为测试资料选择“评测验证”；实际教学资料选择“正式出题”。核实许可和模型外发许可。上传后逐块对照原文，确认所需块。教材受限正文不默认外发。
3. 点击“AI 生成”，选择与资料一致的用途和具体原文块，核对题型数量及要求，提交生成与独立审查。一个任务可能有生成、独立求解、答案比较与冲突复核多个实际调用。
4. 在“备题任务”读取进度；成功后打开题目详情，复核题干、选项、答案、解析、评分点、来源和审查记录。评测题保留为候选，不进入学生任务。
5. 在题库选择明确版本，点击“导出所选完整题目”，可下载 JSON、CSV、HTML。生成任务完成后如仍显示旧列表，点击“刷新”读取已保存版本。重新打开下载文件复核；JSON 保存完整结构，HTML 适合阅读打印。题目包含答案，按教师成果保管。
6. 新资料可随时追加。停用阻止后续使用；需要修正版时先上传、核对并确认新材料，再明确执行替换。历史题目保留原版本和冻结出处。修改已确认原文需建立新材料。

## 导入历史学情并形成分析成果

在“学情分析”点击“新建分析”，选择六份 CSV：课程要求、题目与材料、模拟学生、测验节点、作答记录、字段说明；也可选择包含对应工作表的 XLSX。索引的“数据说明”可一并输入。现有输入模板的文件名和字段继续保留；新数据使用自己的学生、班级、题目和节点编号。原文件不被覆盖，同表一致输入去重，不一致输入明确拒绝。

保存预览后核对文件摘要、逻辑行数、异常和字段字典，再选择实际载入的节点、班级、学生子集、分组和代表学生。教材未声明主题或指标时由操作者确认映射。确认范围后结果冻结；相同确认重试返回原结果，更改范围需要新建分析。创建响应中断时从原请求回读或重试，保留同一请求和原输入。

成果包含要求与材料映射、分节点个体表现、班级与分组统计、两班共同范围、代表案例及逐生行动建议。建议引用已载入且有效的具体材料记录；证据不足时保留限制，不将得分直接解释为独立完成能力或因果进步。统计程序计算的成果明确标注，不冒充模型生成。

导出 JSON 获取完整冻结结构；HTML 用于中文阅读；ZIP 含完整 JSON、多表 CSV、说明、字典、来源及清单摘要。超长 CSV 单元格通过分片文件完整保存，按包内 README 重组。重新打开导出，核对分析记录、输入摘要、人数和分母。历史修订不重复计分，未评分不补零，异常不截断或回退旧高分，不同测量范围分开解释。

## 备份与验收记录

结束操作后先停止服务与 worker，再按 [备份说明](六库备份恢复操作.md)执行 `app.backup_cli backup --stopped` 与 `verify`。原六库必须齐备；存在 `competition.sqlite3` 时一并保存，不能漏掉分析记录。恢复只写隔离新目录，校验与复核后再启用。

2026-11-18 已使用主办方 `课程要求.csv` 的真实原文，通过页面完成生成、独立求解和答案比对，获得两道评测候选题；答案、评分点和冻结来源已核对。完整验收范围见 [本机教学功能验收记录](2026-11-18_本机教学功能验收记录.md)。自动回归、原件复算、浏览器操作和真实供应商调用分别记录。二十分钟演练只有实际连续计时完成后才能记录通过。原始文件、账号、密钥、Cookie、数据库和受限成果不提交 Git。
