## 实际跑过的使用流程

真实服务启用正式 `/api/v1` 路由和一个后台 worker，使用独立数据目录、独立端口及 Cookie jar；未用 TestClient、替换网关或手动执行 worker 来替代本节流程。

1. 初始化专用管理员，实际登录；教师申请、故障审批回滚、解除故障审批及教师登录。
2. 课程申请、权限拒绝、故障审批回滚和重试；建班、学生创建故障回滚、建立两名学生、激活故障回滚、一次性码重复使用拒绝及实际登录。
3. 通过 HTTP 上传合成资料、确认可见块，验证确认前学生不可读、确认后可读、原件存储路径不公开。
4. 创建目标和发布轮次，检查同源 Origin、角色权限、幂等重放及冲突；两名学生执行与正式题分离的首诊，首诊不计正式成绩，完成后才开放正式卷。
5. 编辑租约竞争、设备接管和旧 fence 拒绝；保存草稿、重放及冲突；提交时注入 outbox 写入故障，检查草稿、版本、attempt、题目结果、outbox 和幂等记录回滚，解除后提交成功。
6. 由实际后台 worker 完成评分：两名学生分别 **500 / 300 分值单位，即 5 / 3 分**；评分完成前答案与分数不泄露，完成后统一开放；每个任务只有一次提交及一个评分 outbox。
7. 从上述同一次操作产生的四条真实作答证据生成报告，检查 HTTP 权限、幂等和快照哈希；实际下载 HTML、PDF、XLSX、JSON、多表 CSV ZIP，校验格式、清单和哈希；跨秒重复 XLSX 字节相同。
8. 学生提交评分异议，实际 worker 程序复核后进入 `awaiting_teacher`，不会自行改正式分；教师追加更正将学生成绩从 5 分改为 4 分，仅新增一条更正记录。源修订由 **37** 增至 **41**，新报告更新，旧报告和旧 JSON 导出保持不变。
9. 公式模板和显式确认通过；音频接口按当前实现返回 `503 / asr_not_configured`。
10. 按实际时钟等待持续计划自动发布第二轮，核对两份新卷使用未用过的已审核题。
11. 终止源服务并等待进程退出后备份六库和上传原件；恢复到新 staging，验证旁文件为空和全部文件哈希；按 Runtime 数据布局组装新目录，启动恢复服务，重新登录并核对任务、成绩、历史报告与资料，最后终止并回收进程。

Windows 上脚本使用 `Popen.terminate()` 停止两个专用 uvicorn 进程，均已 `wait()` 回收，退出码为 1，未触发超时强制 kill。该验证证明写进程停止后可备份恢复，也覆盖了终止后的 SQLite 恢复；不据此宣称已验收优雅关闭信号或所有停机恢复场景。
