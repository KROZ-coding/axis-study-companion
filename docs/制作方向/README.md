# 阿克西斯 · 智慧学伴制作方向

更新：2026-11-08。本文是团队制作指导，不是比赛官方解释，也不是功能已经实现的声明。

> 2026-11-11 后续入口：用户访谈确认的正式产品、前后端设计及首版范围以[技术总方案](../智慧学伴产品与前后端技术总方案.md)和[需求复核清单](../需求覆盖与复核清单.md)为准。本文的赛事任务与证据建议继续供参考；“门户可选”“不加入3D”等历史建议已由最新需求覆盖。

代码承接已按 `audit-companion` 的 FastAPI 基础落地，当前本地运行的数学链路使用虚构样例，并新增服务端诊断与导出接口；正式赛题数据映射与评测尚未完成。来源、许可和启动步骤见[承接与本地部署说明](../本地部署与承接说明.md)。

## 1. 当前结论

**先把题目理解、作品主张与答辩叙事做好，再倒推需要哪些证据、界面和技术。**

目标不是搭建功能齐全的教学管理平台，而是让评委看清：

1. 我们发现了什么具体教学问题。
2. 为什么仅看分数、堆资源或生成通用建议还不够。
3. 我们怎样把学习要求、表现证据与教学安排联系起来。
4. 哪些结果已经验证，哪些还不能确定。

PPT的吸引力来自问题切入、案例递进与视觉表达共同作用；“漂亮”不是最后加装饰，也不能代替准确结果。先做故事板，不等全系统完成才写材料；同时用证据不断修正故事，不能预先锁死未经验证的结论。

## 2. 建议的作品主张

暂用主张，待团队讨论确定：

> 阿克西斯：让每一条学习建议，都有可追溯的依据。

更完整的价值表达：

> 把分散的教育资料，转化成教师看得懂、学生做得到，并且与证据相称的学习支持。

可追溯是可信基础，不能单独当作已证明的创新；亮点还应体现具体教学价值。

| 建议重点 | 要回答的问题 | 必须准备的证明 |
| --- | --- | --- |
| 有边界的学情判断 | 哪些表现有依据，哪些尚不能判断？ | 表现与覆盖分开呈现，给出记录依据和判断限制 |
| 从错步到学习行动 | 相似得分背后的具体问题是否不同？ | 原题、步骤、评分点与针对性建议之间的对应 |
| 教师可理解、可调整 | 建议为何这样安排，怎样改变？ | 明确理由、顺序与观察条件；交互调整是可选增强 |

这是制作建议，不是官方规定的唯一创新点；未验证前不宣称“首创”“显著提分”或“精准识别所有错误原因”。

## 3. 对赛题的理解

课程要求说明应学到哪里，学生表现说明已有何种证据，学习材料说明可以如何支持学习。

三项任务应在同一案例中连起来，而不是做成三个互不相通的菜单：

**学习要求 → 已有表现及信息缺口 → 具体建议与材料 → 后续观察条件。**

- 对教师，重点是理解共性、差异、依据与安排；对学生，重点是明确当前行动。
- 一次错误不等于稳定能力缺陷或心理原因；少量全对也不证明全范围掌握。
- 信息不足是有效分析结果，不是必须用分数填满的空白。
- 个性化不是每人获得不同文案，而是不同证据支持不同的教学安排。
- 学习活动不只有刷题，还可包括解释理由、比较解法、检查步骤和核验结果。
- 真实教学场景要求使用逻辑合理，不等于必须采集真实学生资料。

## 4. 必交内容与选做增强

正式细节以本地规则、参赛说明与典型案例说明为准；完整对照保存在本机 `本地参赛工作包/需求对照与案例证据.md`。

| 内容 | 制作要求 | 边界 |
| --- | --- | --- |
| 学习内容梳理 | 内容、要求、必要联系、课标及材料出处 | 图谱可选；题库目录不能替代学科梳理 |
| 学情分析 | 数据处理口径，个体与群体表现，依据和信息不足 | 不强制输出掌握概率，不把缺失当零分 |
| 学习建议 | 具体材料、理由、顺序、提示及后续观察 | 需说明提示与观察条件，不必做完整在线练习系统 |
| 典型案例与班级分析 | 正式说明要求的三名代表学生及两个班级比较 | 案例类型是参考；演示案例不应被硬编码成算法 |
| 设计方案PDF | 不超过20页，含需求、方案、功能、验证和创新 | 与答辩PPT职责不同，不能只放截图 |
| 任务成果包 | 三项任务的JSON、CSV等机读结果及字段、样例、操作说明 | 不能用截图报告代替机读成果 |
| 演示视频 | MP4，5分钟以内，展示三任务、案例与依据查看 | 只录页面切换不足以证明完成任务 |
| 现场答辩PPT | 10分钟讲解，5分钟答辩 | 建议约12页主讲页，页数不是官方限制 |
| 分析脚本或代码 | 可选提交 | 不交代码也要能核对关键输入与输出 |

资料评审占80%，现场答辩占20%，不是PPT美观占80%。四个评分维度没有分别公布百分比；同分时先比较学情分析，再比较学习建议质量。

选做增强包括教师交互调整、补充记录后的建议更新、在线练习与持久化、动态图谱等。先选一个能证明价值的增强点，不同时铺开。

**特别区分：案例中的分步提示、后续观察和调整条件需要呈现；完整的在线练习反馈系统属于增强。**

## 5. PPT故事板

开场建议用“少量题目全对，是否足以判断全面掌握”的模拟案例，迅速展示问题，而不是先讲多页行业背景。

| 页 | 要让评委相信的结论 | 需要准备的内容 |
| --- | --- | --- |
| 1 | 我们解决的是有依据的下一步学习安排 | 项目名、主张、一处可读案例画面 |
| 2 | 全对记录不等于全范围掌握 | 表现与覆盖的矛盾、来源及范围 |
| 3 | 我们理解三项任务为何要联系起来 | 要求、表现、材料与建议的简图 |
| 4 | 分数之外，步骤提供更具体的证据 | 一道解答题的原题、步骤、评分点 |
| 5 | 判断应有边界，不把推断当事实 | 观察事实、有限判断、待核实项的对照 |
| 6 | 诊断能够变成可执行的教学安排 | 材料、顺序、分步提示、观察条件 |
| 7 | 不同需求得到合理不同的安排 | 三名代表案例对照，而非三段套话 |
| 8 | 个体证据也能支持群体分析 | 两班同口径比较，标明节点和覆盖 |
| 9 | 教师能够复核并理解建议 | 依据查看；已实现时再演示交互调整 |
| 10 | 系统职责明确，结果可核验 | 数据校验、程序统计、AI解释和人工复核的分工 |
| 11 | 关键结果经过检查，不只是界面可用 | 实测统计、引用和建议检查结果，列明限制 |
| 12 | 作品价值是支持更合理的学习行动 | 回扣开场，明确已完成与后续方向 |

标题写结论，例如“记录少，不等于能力弱”，而不是只写“学情分析模块”。故事板不是已完成的实验结果，每个结论都要找到对应证据。

建议讲解预算：问题与主张1分钟，学科及案例分析3分钟，差异化建议与班级分析2分钟，产品与技术1.5分钟，验证与收束2分钟，预留0.5分钟。

备用页准备数据口径、案例来源、异常处理、模型职责、材料定位和限制说明；主讲不逐行讲实现细节。

## 6. 前端与视觉方向

老师的22张截图是布局与操作意图参考，不是必须复刻的系统，也没有可直接复用的对应源码证据。

前端允许大改，建议围绕五类任务收敛：

| 视图 | 主要用途 |
| --- | --- |
| 教师工作台 | 共性问题、个体差异、覆盖与需复核事项 |
| 学生证据页 | 就近查看原题、作答、评分点、指标和判断边界 |
| 建议与材料页 | 为什么推荐、先做什么、后续观察什么 |
| 学生任务预览 | 清楚展示一步行动与分层提示；在线作答闭环为增强 |
| 成果与复核页 | 查看三任务结果及依据，导出机读成果 |

- 不强制建设独立师生门户或完整权限系统；演示角色切换不等于真实权限。
- 保留原型的证据展开、材料查看和案例跳转；不要让学生先进入全量目录找推荐内容。
- 以中性底色、可读中文与公式、稳定布局为主；数学批注用于实际步骤，不用装饰替代证据。
- 同一套状态标记贯穿PPT与原型，同时用文字说明，不只靠颜色表达证据不足。
- 截图裁切放大关键交互，不将复杂工作台缩成不可读缩略图；正文不能藏在长资源列表之后。
- 入口、交接、报告可考虑少量辨识性动效，工作台克制；这是可选策略，不是强制实施项。
- 暂不搬入签到、勋章、排行榜、课程思政和复杂教务管理，也不为展示技术加入3D场景。

## 7. 制作顺序与通过条件

| 阶段 | 产物 | 通过条件 |
| --- | --- | --- |
| A：确定主张 | 一句话定位、三个重点、约12页故事板 | 每个重点对应任务和证据，不靠技术名词支撑 |
| B：准备证据 | 学科映射、数据口径、三案例与两班分析 | 事实可复算、引用可定位、未知项明确 |
| C：验证核心画面 | 一个完整案例证据页及建议页 | 原题、记录、解释、材料对应，下一步可理解 |
| D：组织智能体能力 | 结构化输入输出与必要解释/建议生成 | 说明AI实际职责；规则基线、模型输出、人工修改分开标记 |
| E：完善材料 | 方案、机读成果、视频与PPT | 四类材料同口径，同一案例结果一致 |
| F：彩排与复核 | 计时讲解、问答清单、离线备份 | 不超时，关键问题可回到证据，演示失败有已核验结果备份 |

A与B可迭代推进。不必等待全系统完成，但不能在证据核验前把讲稿结论锁死。

技术路线未锁定。建议程序完成可复算的整理与统计，再考虑AI辅助解释和建议，这是方案选择，不是比赛强制架构。无需先微调模型、建设复杂多智能体或大规模向量库。

## 8. 验收清单

- [ ] 三任务有明确成果，且能在同一案例中对应。
- [ ] 正式说明要求的代表学生与两个班级均覆盖。
- [ ] 修订、待评分、未作答、异常和覆盖不足分别处理。
- [ ] 诊断能指向对应记录，材料引用确实存在。
- [ ] 观察与原因推断分开，不用“粗心”等词替代证据。
- [ ] 案例建议有合理差异，说明材料、顺序、提示和观察条件。
- [ ] 不把节点总分差、一次答对或模拟反馈当作真实教学效果。
- [ ] 未实现功能明确标为设计，不把预设样例说成模型实时生成。
- [ ] PPT投影可读，视频与讲解时长合规，公式和来源可检查。
- [ ] 成果包可机读，附字段、输入输出样例与操作说明。
- [ ] 原始资料、案例原文、提取内容和受限产物没有进入Git或未获许可的外部服务。

验证指标先写口径，不填目标成绩：统计复算差异、引用可定位率、必需字段完整性、案例建议复核记录。只有实际执行检查后，才能填入结果；合理性判断还应说明人工复核标准。

## 9. 资料位置与待定事项

完整工作包在本机 `本地参赛工作包/`，包含规则旁注与需求案例对照，不上传。

待确认：作品名称与主张、重点创新点、校内截止及要求、企业选拔提交安排与模板、独立评测方式，以及第三方模型服务的数据处理许可。

正式赛事时间以官方通知和学校安排为准，不使用未核实的网页日期安排制作。
